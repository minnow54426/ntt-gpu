01

The data is just a list of numbers

Forget everything else. The only object this page needs is a list of N numbers — in math language, a polynomial. Like this:

3slot 07slot 1 1slot 29slot 3 4slot 40slot 5 5slot 62slot 7

N is big — 1024 to 65536 entries — and the one operation that must be fast is:

multiply two lists of length N, get back a list of length N

The NTT (Number Theoretic Transform) is how that multiplication gets done fast. (How the product stays length N — the fold rule — is chapter 9's story.)

02

The wheel: powers of a root of unity

Meet the number the whole transform runs on. Watch it being born, mod 17 — start at 1 and keep multiplying by 2:

The wheel — the eight powers of 2, mod 17 · start at 1, keep multiplying by 2
dashed diameters: opposite points sum to 17 = q — each is the other's negative (property iii, halfway = minus)

Eight different numbers, then the ninth step lands back on 1. The powers of 2 form a closed loop of exactly 8 points — a wheel. Such a number is a root of unity ("unity" just means 1): ω^N = 1, and primitive if no earlier power comes home. Everything the NTT relies on is a property of this wheel:

Nothing sacred about 2 — mod 17 offers four primitive 8th roots: 2, 8, 9, 15. Each walks the same eight points in a different order; 2 just gives the easiest multiplication table.

i.

Closed: multiply = move

Powers never leave the wheel: ωᵃ·ωᵇ = ω^(a+b) — multiplying just adds positions, a clock for multiplication (the logarithm trick). Why: one number generates all N plug-in points, one multiplication each.

ii.

Distinct: nothing is lost

A primitive root visits N different points, so N plugged-in values pin the list down exactly — the coordinates are reversible. Why: the transform has an inverse. The one demand on the prime: N | q−1 (ntt.hpp:61).

iii.

Halfway = minus

ω^(N/2) = −1: opposite points are negatives (above: 1↔16, 2↔15, 4↔13, 8↔9 — each pair sums to 17). Why: the ± that makes output pairs — the butterfly's two wings (chapter 6).

iv.

Squaring = a half wheel

Every second point closes after N/2 steps: a half-size wheel with root ω². Why: wheels nest — the transform builds itself from half-size copies, the source of every "repeat" in chapter 5.

Why not just any N distinct numbers?

Any N distinct points make chapter 3's trick correct. Only wheel points make it fast: the shared brackets of chapter 5 are this wheel's symmetries showing up as algebra. The speed of the NTT is wheel symmetry.

03

The equation of the NTT

A list like (2, 1) is a tiny machine: plug a number t in for x, get a value out. And plugged-in values multiply one by one:

(A·B)(plug in t) = A(plug in t) × B(plug in t)

One multiplication, no crossing terms — and it holds for every t. Both roads below use t = 2 (mod 5); change any coefficient and they still agree:

Road 1 costs four multiplies and still knows the product at only one point. Road 2 costs one multiply — and the equation below runs Road 2 at every wheel point at once.

To pin the product down we need its values at N different points — chapter 2's wheel supplies them.

the definition · the whole transform in one line
Aⱼ = a₀ + a₁·ωʲ + a₂·ω²ʲ + a₃·ω³ʲ + … (mod q)

Evaluating the list at all N wheel points is the NTT. Output j is the list plugged in at wheel point ωʲ — and because the points are distinct (wheel property ii), the transform inverts:

evaluate → multiply pointwise → invert  replaces a list multiplication with N plain multiplies. The rest of this page makes that round trip cheap.

Why "NTT" and not "FFT"?

The FFT does this with decimals — but decimals round, and rounding errors compound. The NTT does the same idea with whole numbers mod a prime: exact forever. Its wheels exist whenever N | q−1 — checked at ntt.hpp:61.

05

Expand the equation — the repeats jump out

Here is the fast algorithm, discovered the honest way. Chapter 3's equation makes every output a sum of four products, and chapter 4 says computing them separately costs N×N. So take a list of four numbers a = (a₀, a₁, a₂, a₃) and write all four outputs out longhand, hunting for work that repeats. (Remember ω has order 4 here — ω⁴ = 1 — so exponents wrap: ω⁶ = ω², ω⁹ = ω.)

A₀ = a₀ + a₁ + a₂ + a₃ A₁ = a₀ + a₁ω + a₂ω² + a₃ω³ A₂ = a₀ + a₁ω² + a₂ + a₃ω² A₃ = a₀ + a₁ω³ + a₂ω² + a₃ω

Four outputs × four terms — sixteen products if you charge ahead blindly. Now regroup every line, even-position terms first, odd-position terms second, and stare at what repeats:

A₀ = (a₀ + a₂) + (a₁ + a₃) A₂ = (a₀ + a₂) − (a₁ + a₃) A₁ = (a₀ + a₂ω²) + ω·(a₁ + a₃ω²) A₃ = (a₀ + a₂ω²) − ω·(a₁ + a₃ω²)

The same two brackets sit inside both outputs of each pair — and the multiply ω·(a₁+a₃ω²) is shared too. One more squeeze: halfway around the wheel is minus (property iii), ω² = −1, so (a₀+a₂ω²) = a₀−a₂ and (a₁+a₃ω²) = a₁−a₃. Extract the four inner results:

p = a₀ + a₂ q = a₀ − a₂ ← one butterfly (w = 1) r = a₁ + a₃ s = a₁ − a₃ ← one butterfly (w = 1)

The brackets are already butterflies — each line is one unit fed with two raw coefficients. The final assembly is two more:

A₀ = p + r A₂ = p − r ← one butterfly (w = 1) A₁ = q + ω·s A₃ = q − ω·s ← one butterfly (w = ω)

Count: 2 + 2 = 4 butterflies — (N/2)·log₂N for N = 4, and exactly stages 1–2 of chapter 7's picture. Level 1 feeds level 2, and the four outputs fall out.

For general N, name the halves the way the books do — E for the evens-machine, O for the odds-machine — and every pair of slots (j and its opposite j + N/2) is assembled from them:

out[j] = E + w·O out[j+N/2] = E − w·O ← same E, same O, same w — only the sign flips

Where does that minus come from? Wheel property iii

Halfway around, every point is the negative of its mirror: ω^(j+N/2) = −ωʲ (mod 17, ω = 4: ω² = 16 = −1). The repo checks this exact fact at ntt.hpp:66: psi^n == q−1.

One multiply, one add, one subtract; two values in, two out. That is the fast algorithm's only moving part. At N = 8 it simply nests one level deeper — chapter 7's machine, where we go next.

06

Meet the butterfly

You met this unit four times in chapter 5. Draw its formulas as a circuit: two wires in, two out, crossing once — from the side, two wings. Someone in 1969 said "butterfly", and the name never left. It comes in two costumes — same wings, the multipliers ride different legs:

DIT — ① multiply the input, ② add / subtract · what chapters 5–7 derive
DIF — ① add / subtract, ② multiply the difference output · the same unit, run the other way
Same two wings — only the order of multiply vs ± differs (the gold ①②). DIT multiplies before the crossing, DIF after it. (The repo's negacyclic forward adds one refinement on top of DIF — a ladder constant ψ^d on the input leg; that is chapter 10's loop.)

Why are the inputs scrambled?

The leftmost values are in bit-reversed order (0,4,2,6,1,5,3,7 — index in binary, read backwards). That one upfront shuffle lets every stage read its partners from nearby positions and the outputs arrive in natural order. The repo ships the mirror image: a DIF forward (natural inputs, bit-reversed outputs) paired with a DIT inverse that consumes exactly that order — so in the real pipeline the two permutations cancel and no bit-reversal pass exists at all (bitrev.hpp documents the permutation itself).

And the negacyclic variant?

This network is the plain ("cyclic") transform. The negacyclic variant — chapter 10 — is the same network with its stage twiddles scaled by wheel powers: same butterflies, one pass (ntt.hpp:87).

09

The negacyclic variant: the fold rule

One loose end from chapter 1: the operation there was "multiply two lists, get back a list of the same length N." But plain multiplication lengthens the list:

(2 + x) · (3 + 2x) = 6 + 7x + 2x² ← grew from 2 slots to 3

If every multiplication grew the list, nothing could chain. The fix is one fold rule, in exactly two flavors:

x^N = +1 "cyclic" — wrap the overflow back with a plus x^N = −1 "negacyclic" — wrap it back with a minus

The cyclic fold is precisely the world of chapters 3–7: every ω-wheel point satisfies x^N = ω^N = 1. The negacyclic fold is the one this repo implements. With x² = −1 (N = 2, mod 5), the overflow folds back like this:

6 + 7x + 2x² → (6 − 2) + 7x = (4, 7) mod 5: (4, 2)

All numbers live mod some prime (here mod 5) — only the remainder after dividing survives, so numbers stay tiny forever.

Which points respect the minus fold? Those with x^N = −1 — the roots of x^N + 1. They are the odd steps of a doubled wheel: a number ψ with ψ^N = −1 closes after 2N points, and (ψ^odd)^N = (−1)^odd = −1. Mod 17, ψ = 6, and ψ² = ω — its even steps are chapter 2's wheel:

spot-check one highlighted point: 6⁸ = (6²)⁴ = 2⁴ = 16 ≡ −1 (mod 17) ✓  ·  chapter 3's t = 2 mod 5 was exactly an odd step of the small doubled wheel there (2² ≡ −1, 2⁴ ≡ 1)

The twist: same butterflies, one seasoning

Conceptually: multiply the inputs by the ψ-powers table before the network, undo after. The repo's reference goes one better — it folds the twist into the butterflies as ladder constants: stage with pair distance d multiplies the add leg by ψ^d (an odd wheel power — exactly where x^N + 1 lives) and strides the difference leg by ψ^(n/d). One sweep, no tables, no bit-reversal pass, same math (ntt.hpp). That is the entire difference — and exactly what this repo implements.

10

The same shape, hiding in the code

Here is the actual loop from this repo's CPU reference (include/ntt/ntt.hpp, the forward DIF sweep — twist folded in as ladder constants, natural values in, bit-reversed values out). Read the comments with chapter 7 open next to it — every line is a part of the picture:

for (uint64_t d = n_ / 2; d >= 1; d >>= 1) {      // the stages — pair distance halves: n/2, n/4, …, 1
  const uint64_t c = pow_mod(psi_, d, q_);           // ladder constant ψ^d — the twist, folded in
  const uint64_t stride = pow_mod(psi_, n_ / d, q_); // the cyclic stride in disguise: ω^(n/2d)
  for (uint64_t i = 0; i < n_; i += 2*d) {         // each block of 2d wires
    uint64_t w = 1;
    for (uint64_t j = 0; j < d; ++j) {
      const uint64_t u = a[i + j];                            // top input        ←┐
      const uint64_t cv = mul_mod(c, a[i + j + d], q_);    // bottom × ψ^d    ←┤ ONE BUTTERFLY
      a[i + j]     = add_mod(u, cv, q_);                       // top wing: u+cv  ┘
      a[i + j + d] = mul_mod(sub_mod(u, cv, q_), w, q_); // bottom wing: (u−cv)·w
      w = mul_mod(w, stride, q_);
    }
  }
}

Three nested loops, one idea: for every butterfly in every stage — u+v, u−v. The CUDA port ahead just assigns each X to one GPU thread and each stage to one kernel launch. The picture is the architecture.

The whole page in one breath

A root of unity generates a wheel of N exact plug-in points that multiply like clock positions; the NTT is its one-line equation — the list evaluated at every wheel point. Computing that directly costs N² products; expanded longhand, the outputs share brackets, and each shared pair costs one multiply, one add, one subtract — a butterfly. Tiled across log₂N stages, N² collapses to (N/2)·log₂N: at N = 65,536, from 4.3 billion products down to 524,288 butterflies. The negacyclic variant plugs in at the odd steps of a doubled wheel (ψ^N = −1) to multiply under a fold-with-minus rule — the same butterflies inside.
