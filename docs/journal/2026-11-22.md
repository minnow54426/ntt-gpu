# Survey CUDA kernel optimization

## Outcome

The [survey](../cuda-kernel-optimization-survey.md) links timing scopes,
profiler signals and optimization techniques to the existing split NTT.
The first candidate experiments are Shoup twiddle multiplication and
coalesced loading in the strided pass. Their relative impact remains
unverified on RTX 5090.

## Reasoning

The existing Ada comparison showed a median 1.52× device-event forward
speedup for group twiddles and 1.01× for the public forward call. The
different scopes motivate capturing independent timing and profiling records.
The strided pass address calculation suggests a sector-efficiency
opportunity. Actual traffic depends on cache reuse and needs counters.

## Changes

Added and registered the research article. It covers integer arithmetic,
memory access, launch geometry, inverse normalization fusion, and the
conditions for testing batching or CUDA Graphs.

## Verification

Reviewed the CUDA kernel, shared butterfly, modular arithmetic and recorded
Ada results against NVIDIA's documentation and published NTT studies.
The current macOS arm64 environment provided neither `nvcc` nor
`nvidia-smi`. This work collected no native GPU measurements.

All 27 Python documentation tests and 14 JavaScript lesson tests passed.
The site builder validated links and generated 51 pages, including 18
journal entries. The browser blocked local-file preview, so desktop and
mobile visual review could not be completed.

## Open questions

RTX 5090 kernel counters and native acceptance remain open. Shoup table
traffic and the cost of rearranging column accesses need measurement.
