# Define and accept the device backend architecture

## Outcome

Completed the [D9 backend proposal](../device-backend-contract.md). The
[roadmap](../openfhe-integration-plan.md) advances to D10's architecture decision
and implementation backlog. P1 remains in progress until that review accepts
the proposal. This change implements host metadata checks and compile-checked
abstract interfaces; a CUDA runtime backend and OpenFHE adapter remain proposed.

## Reasoning

D7 fixes representation and D8 fixes the exact Hybrid graph. A pointer/length
API would still lose the active Q prefix, full-key P offsets, exact roots,
producer completion and ownership of scratch/key material. The design keeps
those facts together in immutable snapshots and checked whole-tower views.

The first integration seam is an explicit opt-in DCRT format-conversion adapter.
It uses a private host candidate and commits only after complete success.
CPU fallback is allowed only during preflight; invalid data and runtime failures
are errors. Immutable public inputs and fresh outputs simplify initial alias
and concurrency rules, with possible device-to-device copies counted as a cost.

## D10: accept architecture and close P1

### Outcome

Accepted [ADR 0001](../architecture-decision.md) and the
[implementation backlog](../implementation-backlog.md). The
[roadmap](../openfhe-integration-plan.md) now marks P1 DONE and points to D11.
P2 remains NOT STARTED pending native GPU provisioning. This acceptance freezes
behavioral contracts and implementation priorities; it does not implement or
validate the CUDA runtime backend or OpenFHE adapter.

### Reasoning

The D1–D9 evidence establishes stage/index arithmetic, exact representation,
the pinned Hybrid graph and checked metadata. Review identified two design gaps
that needed explicit decisions: resource admission limits, and resource ownership
when work is partially submitted but event recording or handle publication fails.

The ADR retains pins before the first enqueue-capable call, preserves failed
operation records without returned handles, and requires drain/quarantine rather
than immediate reuse. It chooses separate configurable cache/device-workspace/
host-staging ceilings of 256/256/128 MiB, one initial stream and one adapter
transaction per session, with fail-fast admission. These are conservative design
limits rather than measured optimal settings.

The DCRT adapter remains the first integration seam. `RequireDevice` is its
explicit default; invalid data and resource errors cannot silently fall back.
Only valid unsupported/unavailable/unverified operations may use an explicitly
permitted CPU route before submission. Candidate import precedes the pinned
nonthrowing DCRT move commit. Upstream allocating `noexcept` operations and the
shared FTT cache's missing root identity remain explicit limitations.

### Changes

## Offline preparation before GPU rental

### Outcome

Completed the [offline preparation](../offline-gpu-preparation.md) for the first
native session. Real nvcc builds and links both sm_89 and sm_120 targets, including
a new direct CUDA/OpenFHE exactness program. The collector returns `OFFLINE_READY`
after 19 host/OpenFHE tests and explicitly leaves four GPU tests unrun.
D11 remains the current working day: its actual hardware/driver record cannot
be completed in this driverless workspace. P2 preparation is now IN PROGRESS.

### Reasoning

The user asked to finish work that can be done before renting. Compiler-only
validation finds expensive setup failures without charging GPU time. CUDA
12.8.93 failed compiler identification on this host's glibc 2.41 because of
math-header exception-specification conflicts. A stock CUDA 13.0.88 compiler
from the 13.0.2 redistributable release works here; vendor headers were not patched.

The first nvcc build exposed the existing CUDA file's missing namespace closure.
Free launch helpers now deduce the private implementation type without exposing
it publicly. The original raw-Impl construction path also needed unique ownership,
while default CMake detection and the old benchmark pipeline could misclassify
incomplete/failed work as success. The changes address those offline blockers
without claiming native execution or performance.

### Changes

- Added a SHA-256-locked local NVIDIA compiler/runtime/header installer, preserving
  licenses and leaving drivers/system packages unchanged.
- Added explicit CMake CUDA enable/require controls, a shared CUDA backend library,
  GPU labels, host validation/constructor targets, and compiler-only CI.
- Changed the synchronous wrapper to unique Impl ownership and owning-device
  guards. Added checked dimensions/counts, prime/root bounds and canonical input
  rejection; preserved the six-buffer dataflow and arithmetic stage bodies.
- Added the N=65536 direct CUDA/CPU/OpenFHE comparison program: exact-width
  55/50/60-bit primes, D8 Q/QlP bases at L=5,4,3,1, seven coefficient patterns,
  independent inverse input, round trip, pointwise/inverse and ring product.
  It is compiled but not run on a GPU.
- Replaced the AutoDL helper's implicit pull/install and fragile verdict with
  explicit session collection, immutable report directories and stage logs.
  Missing coverage or failed build/test/sanitizer/benchmark stages return nonzero.
- The pinned OpenFHE helper now explicitly selects its 64-bit/no-reduced-noise
  CPU build and bounded parallelism, so offline preparation cannot accidentally
  execute newly detected GPU tests.
- Updated the D5 map, roadmap/backlog, source guidance and website catalog.
