# Define device buffers and the backend integration boundary

## Outcome

Completed the [D9 backend proposal](../device-backend-contract.md). The
[roadmap](../openfhe-integration-plan.md) advances to D10's architecture decision
and implementation backlog. P1 remains in progress until that review accepts
the proposal. This change implements host metadata checks and compile-checked
abstract interfaces; a CUDA runtime backend and OpenFHE adapter remain proposed.

## Reasoning

D7 fixes representation and D8 fixes the exact Hybrid graph. A pointer/length
API would still lose the active Q prefix, full-key P offsets, exact roots,
producer completion and ownership of scratch/key material. The design keeps
those facts together in immutable snapshots and checked whole-tower views.

The first integration seam is an explicit opt-in DCRT format-conversion adapter.
It uses a private host candidate and commits only after complete success.
CPU fallback is allowed only during preflight; invalid data and runtime failures
are errors. Immutable public inputs and fresh outputs simplify initial alias
and concurrency rules, with possible device-to-device copies counted as a cost.

## Changes

- Added [backend_contract.hpp](../../include/ntt/backend_contract.hpp): immutable

  operation layouts, dependencies, cache identities, retirement and hoist rules.

  and prepared the website export with the existing readable theme and sidebar.

## Verification

The portable contract executable passes 78 checks on Linux x86_64/GCC 14.2.
The same test passes AddressSanitizer and UndefinedBehaviorSanitizer with no
reported issues. Tests include invalid roots, canonical values, overflow,
incorrect reduced-QP spans, stale generations, overlap, missing cross-stream
waits, failed-resource retirement, changed cache identities and forbidden
post-submission CPU fallback.

Final local verification:

- All 23 documentation unit tests and 14 Node interaction/math tests passed.
- The documentation build generated 25 HTML pages, including eight journal
  entries, and validated local links, fragments, assets and catalog coverage.
- Chromium passed 100 page/width checks across all 25 notebook pages at
  1440/1024/375/320px: English content, rendered formulas, no page-wide overflow,
  and no script or failed HTTP responses. D9's section links and search worked;
  its article, this entry, the roadmap and both introductory lessons passed
  computed text-contrast checks. The tracker displays D10. Desktop and phone
  screenshots of the new article were inspected.

Publication exports the source article and journal to the existing personal
website, preserving section navigation and the shared design. Deployment and
live verification follow the website push. These are CPU/metadata and browser
gates; no CUDA compiler or real GPU is available in this environment, and no
GPU correctness or performance result is claimed.

## Open questions

cache budget/backpressure, failure quarantine and ordered implementation backlog.
Runtime tests still need allocation/upload fault injection, cache races,
asynchronous error/drain handling, completion abandonment and host rollback.
Production Hybrid conversion/key-family coverage remains later work.
