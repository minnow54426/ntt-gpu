## Reasoning

The inverse uses the same column pairs and exponent indices as the forward
transform, but reciprocal powers. Untwiddle the difference leg first, form
sum/difference, then apply the inverse ladder to the lower result. This
composition returns twice the original pair. Reversing all log2(N) stages
returns N times the input, so one final modular N-inverse scale suffices.

The inverse must execute near row stages first, far column stages second,
and scaling last. This is three launches at both endpoint sizes, not two.
The bit-reversed evaluation output of forward is the inverse's direct input;
neither direction needs a separate bit-reversal pass.

## D6 follow-up: arithmetic bounds and adversarial tests

### Outcome and reasoning

D6 is complete; the live tracker advances to D7, not past the P1 architecture
gate. [The arithmetic contract](../modular-arithmetic-contract.md) records
preconditions, temporary-width proofs, canonical-range induction, the exact
test ladder and a concrete deferred adversarial checklist. No reduction
algorithm, kernel geometry or public API changed.

The implementation uses canonical residues after every operation, not lazy
reduction. A 60-bit modulus still needs a product wider than uint64_t.
The arithmetic-header comment incorrectly counted CPU butterfly multiplies:
the CPU loop uses three including twiddle advance; shared device helpers use
two with table lookup. Corrected the comment and made q>0 explicit.
