# Make the 4096-point CUDA schedule tangible

## Outcome

Added a standalone HTML learning page explaining the current forward CUDA
schedule using a concrete 4096-coefficient polynomial and one RNS limb.
No CUDA implementation or roadmap gate changed.
Later follow-up: completed the D1 index/memory map for both target extremes
and advanced the working-day tracker to D2; the P1 architecture exit gate
is still open.
Subsequent D2 work completed the column index/twiddle proof and exhaustive
stage-helper checks; the tracker now points to D3 inverse-column work.

## Reasoning

Reading individual source lines made it hard to see the whole schedule.
The explanation starts with which data each block loads: columns for four
far-distance stages, then rows for eight near-distance stages in the original
4096-point example. Readers can select a stage, block and thread to see
the changing pairs and threads with no butterfly to compute.

## Open questions

Only part of each block computes butterflies in the first pass, and
neighboring threads read widely separated global addresses. We need real
GPU checks and measurements before deciding how to improve that schedule.
