# Freeze the next rental's source and benchmark inputs

## Outcome

Prepared all eight benchmark vector/reference sets and a fresh CKKS rotation
fixture for N=65,536 with five and three active Q towers. Replayed the
individual and hoisted rotation paths using the host transport. Added a
portable source/data handoff for the next RTX 4080 SUPER session.
No rental was created and no native GPU work ran.

## Reasoning

The new Hybrid adapters need native validation before their GPU performance
can be assessed. A rental should restore an exact source revision, use the
same ciphertexts, keys and expected answers, and retain separate evidence for
host checks, compilation and native execution. Packaging must preserve that
distinction. The public beginner guide also needs to explain which new
features have only been checked offline.

## Changes

[`prepare_rental_bundle.py`](../../scripts/prepare_rental_bundle.py) creates a
Git bundle, copies the eight hash-checked vector/reference pairs and rotation
fixture, and includes a portable `handoff.py`. It verifies the completed
archive against its source bytes and writes checksum sidecars. It refuses
dirty source, incomplete inputs and existing output paths.

The portable helper verifies the package before checkout, restores the pinned
commit into a new directory, and validates a plan against that clean checkout.
It prints the complete GPU command for later, including rotation timing,
extended public-call repeats and the large conversion trace; it never runs
that command. Optional verification records retain their original revision
and scope. The archive contains source/data rather than reusable binaries.

Updated the [rental runbook](../next-gpu-rental.md#freeze-the-source-and-prepared-inputs)
and the short public results page. The public site remains a six-page guide
with the existing theme, diagrams and Three.js explorers. Its new status
distinguishes CPU-verified Hybrid operations from pending GPU validation.

## Verification

A fresh Release CPU/OpenFHE build passed all 34 CTest entries. The rotation
fixture replay passed two measured pairs at each of five and three active Q
towers. Its four JSONL records identify the backend as `host_simulation`;
these are protocol and correctness checks, not GPU timing evidence.

All 88 tooling tests passed, including four real-Git handoff tests. Those
tests use small synthetic inputs and check archive verification, exact source
restoration, portable replanning, changed/missing/extra files, symlinks, dirty
source, missing workloads, invalid fixtures and mismatched revisions.
The 18 JavaScript lesson/model tests also passed.

Compiler-only checks use a clean worktree at `f72639f`, the implementation
revision pulled at the start of this work. The packaging and documentation
changes do not alter its C++ or CUDA implementation. Compilation records keep
that original commit; they are not reusable-build proof for a different source
revision. The final handoff records its own committed source and input hashes.

Both schedules compiled for sm_89 and sm_120 with CUDA 13.0.2, including the
native Hybrid fixture and rotation benchmark. Each schedule then passed 36
host-only CTests; both reports finished as `OFFLINE_READY` with GPU execution
marked `NOT_RUN`. All 33 documentation tests passed. The builder validated
55 full-notebook pages and the six-page public export.

Chromium checked all 25 public website pages at 1440, 1024, 375 and 320 pixels.
English content, horizontal layout, guide contrast, theme, search and the four
SVG/Three.js explorers passed. The new results section explains the offline
scope. The full runbook and this journal were also checked at desktop and
phone widths. These browser checks use software rendering, not native CUDA.

The full-size handoff exposed a checksum-ordering bug: `Path` sorting groups
a directory's children before a sibling such as `cuda-comparison.json`, while
string sorting orders that sibling first. The archive byte check passed,
but the portable verifier rejected the differently ordered checksum listing.
The verifier now compares complete filename/checksum mappings and rejects
duplicate entries. The regression fixture includes both nested directories
and prefix-sharing siblings, and also checks reordered checksum lines.

## Review and simplify the runtime and docs

The review focused on resident submission/lifetime code, the OpenFHE bridge,
handoff and batch tooling, and the current setup and rental documentation.
Identical event/allocation/failure steps were repeated in four runtime paths.
The rental page also mixed the current batch with older manual commands and
contradictory status statements.

Added a private `Session::open_state()` admission guard and
`State::submit_output()` for upload, transform, pointwise and join. The latter
uses the already reserved allocation capacity and retains event creation,
allocation, enqueue, completion recording and result construction under one
failure guard. Reservations and pins still exist before any native work.
The operations' transport order, counters and immutable outputs are preserved.

Boundary validation, conversion constants and two-output Hybrid submission
remain explicit. The OpenFHE wrappers have different update and permutation
rules, so those distinctions stay visible in their existing functions.
No arithmetic or kernel schedule was changed and no speedup is claimed.

Reduced the rental runbook from 453 to 234 lines. It now gives preparation,
source freezing/restoration, profiler preflight, the full batch and evidence
export in order. The current command includes the rotation fixture. Moved
advanced binary-reuse requirements to the collector guide and retained all
existing runbook heading anchors. Fixed stale README, resident/conversion
guides, backlog, procedures and catalog summaries that treated the already
recorded conversion run as pending. Dated journal observations and measured results retain their scope.
The public guide is shorter and preserves its previous offline-status bookmark.

The final CPU/OpenFHE suite passed all 34 CTests. Resident tests passed 499
control checks, including new moved/closed-session checks across all admission
entry points. AddressSanitizer, UndefinedBehaviorSanitizer and leak detection
passed those same checks. Both CUDA schedules compiled the backend, resident
fixture and Hybrid fixture for sm_89 and sm_120. Tooling, documentation and
lesson checks passed 88, 33 and 18 tests respectively.

Browser checks passed for all 25 public pages at 1440, 1024, 375 and 320 pixels,
including search, contrast, the preserved offline-status link and all four
SVG/Three.js explorers. Eleven detailed-page/anchor cases also passed at
1440, 375 and 320 pixels with expanded notes. The full builder validated all
55 notebook pages and local links.

Native GPU execution remains queued. The earlier rental archive stays pinned
to `2b262aa`; a run of this refactored source requires a fresh handoff and
matching build records. This review does not advance D11/P2.
