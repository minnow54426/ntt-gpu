# Restore the website's earlier visual design

## Outcome

Restored the earlier website design from Git history at the user's request.
The portfolio uses its Sunlit Paper palette, Anton/Space Grotesk typography,
photo-filled lettering and full-width photo grids. The research notebook
returns to its earlier green and paper theme with an expanded page directory.
Current articles, journals, native GPU results and roadmap state are preserved.

Later the same day, the user asked to apply the portfolio theme to the NTT-GPU
pages. The notebook now shares Sunlit Paper backgrounds, burnt-orange and
forest-green accents, Anton headings and Space Grotesk body text. The earlier
restoration remains recorded above; the original design is also backed up on
the website repository's `backup/old-website-design` branch.

The subsequent engineering increment completes the benchmark collection split:
GPU-only measurement jobs for rentals, an independent CPU-only session mode,
and explicit combined collection for compatibility. No GPU was rented and
D11/P2 remains open.

The next increment implements a bounded resident operation-chain prototype:
upload two inputs, transform, multiply, inverse and download. The deferred host
transport passes exact OpenFHE comparisons; the CUDA adapter and matching native
fixture compile for sm_89 and sm_120. No native execution or speedup is claimed,
and D11/P2 remains open.

## Reasoning

The November 11 shared blue/white redesign changed the visual identity beyond
what the user wanted. Restore the presentation from the preceding revisions
without reverting the repository or losing later engineering work. Keep the
English text, readable lesson panels, keyboard navigation and current controls.

The follow-up explicitly requests a common theme. Keep the portfolio's visual
identity while tuning type sizes, code surfaces, tables and controls for long
technical articles. Load the theme from source so exports retain it.

The next rental should spend time on native checks and GPU measurements, not
repeat the local CPU timing sweep. Scope-specific manifests and stable machine
identities prevent mismatched jobs from being reused after a selection change.
CPU reference preparation and exact-result checks remain part of GPU validation.

Keep the new runtime separate from the full proposed backend. Immutable fresh
outputs and one stream make lifetimes and dependencies testable before a paid
session. Retain queued resources whenever failed submission cannot prove a
drain; production recovery, cache admission and the OpenFHE adapter remain later
work. Preserve the website's shared theme when publishing the new article.

## Open questions

None for the visual work. Future content publishing should retain the
established design unless the user explicitly requests a redesign. For the
collector, native M1 and new GPU-only session execution remain unverified;
primary RTX 5090, native failure handling and full profiling gates stay open.

For the resident runtime, actual device execution, cleanup under a failed CUDA
context and performance costs remain unverified. Permanent quarantine retains
resources conservatively; automatic recovery, pooling, cross-stream scheduling,
thread safety and production adapter/cache behavior are outside this prototype.
