# Read the NTT evaluation and inverse formulas

## Outcome

Expanded [exact evaluation and inverse formulas](../openfhe-representation-contract.md#3-exact-evaluation-and-inverse-formulas)
for beginners. The section now explains the symbols, distinguishes coefficient
indices from stored evaluation positions, and works through a complete forward
and inverse example. The transform contract and implementation are unchanged.

## Reasoning

The compact formulas assumed that readers already knew polynomial evaluation,
fixed-width bit reversal and modular inverses. Explain each operation before
combining them. A four-point example makes the stored ordering visible without
requiring a reader to follow a 65536-element calculation.

Keep the production formulas at N=65536 and label the small example explicitly.
Put the cancellation proof in optional notes, so readers can follow the
calculation before studying why it works.

## Changes

- Added a symbol table for coefficients, memory indices, root indices, roots,
  bit reversal and N-inverse.
- Explained why odd powers are roots of x^N+1 and mapped the first five memory
  positions to their natural point indices and root exponents.
- Read forward as polynomial substitution and inverse as a weighted sum with
  modular normalization. Distinguished negative powers from array indices and
  decimal reciprocals.
- Added N=4, q=17, psi=2 with coefficients `[1,2,3,4]`, stored evaluations
  `[15,11,13,16]`, inverse roots `[9,8,15,2]` and recovered coefficients.
- Added an optional geometric-sum explanation and retained the existing
  diagnostic probes, upstream source citations and section anchor.

## Verification

Direct modular evaluation gives the displayed forward values. Independent
finite-field Gaussian elimination of the evaluation system recovers the
original coefficients. The inverse weighted sums modulo 17 are `[4,8,12,16]`;
scaling by 4-inverse, 13, returns `[1,2,3,4]`.

A temporary C++20 executable using the actual `NegacyclicNtt` header independently
checks the forward result and inverse of the literal displayed evaluation array.
Both pass with compiler warnings treated as errors. All 27 documentation tests
and 14 Node interaction/math tests pass before the final publication build.
These are arithmetic, CPU and documentation checks, not a new GPU run.

The 40-page build, including 14 journal entries, validates local links and
fragments. Chromium passes four focused checks at 1440/1024/375/320px for the
symbol guide, original section bookmark, worked arrays, expanded inverse proof,
formula rendering, contrast and contained table scrolling. All 59 website pages
also pass desktop and phone layout/math checks (118 page/width checks), without
script or HTTP errors. Desktop/phone screenshots were inspected; main equations
use multiple lines and the worked table has compact, explained symbols.
Publication and live checks follow the source commit.
