# Simplify benchmark modes and the website

## Outcome

Reviewed the CPU NTT, shared stage helpers, CUDA wrapper/benchmark, measurement
helpers and website builder. Simplified benchmark selection without changing
NTT arithmetic, kernel launch schedules, exactness checks or timing scopes.
Shortened the main GPU report and reduced homepage clutter. No working-day
gate advances and no new GPU timing results are claimed.

## Reasoning

Two true/false settings represented three measurement modes, which allowed
redundant combinations. Replacing them with named modes makes the choice
clearer. One table now keeps each command, timing label and operation count
together. Existing command-line calls and saved JSONL records still work.

The homepage repeated long URL strings and a roadmap sequence already
available elsewhere. Its GPU status also incorrectly implied that no native
validation had run. Readers need the current result and next action first;
hardware limitations and evidence must remain available without dominating
the page.

## Changes

- [Benchmark modes](../../include/ntt/benchmark_mode.hpp): one shared protocol
  table and a named mode instead of two independent booleans.
- [CUDA interface](../../include/ntt/cuda_ntt.hpp) and
  [command handling](../../src/cuda_cli.cpp): select the mode once; the
  benchmark implementation reads its metadata/counts from the table.
- CMake applies the same host-target options in one list.
- [Website builder](../../scripts/build_docs.py): preserve every page link,
  group the directory into native disclosures, remove duplicate URL text and
  the redundant implementation sequence, and correct the GPU status.
- [GPU report](../batch40-native-analysis.md): one key-results table, three
  findings and the next steps; secondary measurement notes are collapsed.
  Raw evidence and the November 14 journal remain intact.

## Verification

On the M1 Pro, all 18 standalone and 22 OpenFHE CPU CTests pass, including
the measurement/JSONL and exact OpenFHE checks. The CUDA command translation
unit passes host syntax checking with warnings treated as errors. New host
tests cover all three command/mode mappings, timing labels, operation counts,
unknown commands and invalid mode values.

All 24 documentation tests and 14 interactive Node tests pass; the 35-page
build validates every page/journal route and fragment. Browser checks at
1440×960 and 390×844 verify disclosure expansion, phone navigation, the report
and a scroll-contained results table, with no page-level horizontal overflow.
The report shrinks from 257 to 106 source lines. This is host/UI verification,
not a native GPU rerun; primary RTX 5090 validation remains open. CUDA compiler
verification is delegated to the existing driverless CI workflow, not a rental.

## Open questions

The collector still needs a choice between GPU-only rental work and local
CPU measurements when starting or resuming a session. The next performance
tasks are keeping operation chains on the GPU and testing arithmetic and
memory-layout changes. Simplification does not establish a new
performance improvement.
